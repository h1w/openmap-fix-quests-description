# OpenMap Quest Fix

Исправление вкладки заданий на картах подземелий OpenMap для **WoW Forever 1.60.1**. Отдельный подаддон: файлы OpenMap, Questie, OpenMap Dungeon Routes и трёх источников дополнительных заданий не изменяются.

## Установка

1. Нужны включённые **OpenMap** и **Questie** с его базой QuestieDB.
2. Скопируй папки `OpenMapQuestFix` и `OpenMapQuestFixGuideData` в `<игра>/_forever_/Interface/AddOns/`. Вторая папка — необязательный модуль чтения данных установленного ForeverGuide; без ForeverGuide она не загружается.
3. Выполни `/reload`. Если новая папка не появилась в списке модификаций, перезапусти клиент.
4. Открой карту подземелья → панель данжа → **Задания**.

Для удаления отключи или удали только `OpenMapQuestFix` и `OpenMapQuestFixGuideData`, затем `/reload`. Аддон не создаёт SavedVariables и не мигрирует настройки других аддонов.

## Что исправлено

- Данж сопоставляется по **instanceID**, а не локализованному заголовку с названием крыла. Задания монастыря не пропадают на карте кладбища.
- Активные задания показаны первыми: перенос названия, уровень, статус, цели и текущие счётчики. Связь заданий относится ко **всему данжу**, не только открытому крылу.
- Клик открывает описание, цели и награды в той же панели. **Назад** возвращает к списку и его прокрутке. Карта, масштаб, этаж и выбор в штатном журнале не изменяются.
- Карточка использует штатные атласы Blizzard, `QuestTitleFont`/`QuestFont` и шаблоны предметных наград. Обычный журнал не переносится внутрь панели: его глобальные элементы остаются на месте.
- Награды на выбор активного задания читаются из принятой записи клиента, а не из урезанного запроса по ID. Исходный выбор журнала восстанавливается синхронно, в том числе при ошибке; названия/иконки догружаются по ID предмета. Путеводители не подмешивают награды в активную карточку.
- Внутренняя декоративная рамка OpenMap скрыта на нашей вкладке заданий, чтобы не перекрывать «Читать». Внешнее окно, вкладки и прокрутка сохранены; на исходных вкладках рамка возвращается.
- При включённом **CatQuest** показывается его кнопка «Читать» для открытого здесь квеста; состояния «Стоп», «В очередь», «В очереди» относятся к этому ID. Отсутствие CatQuest не мешает просмотру заданий. Озвучку, паки, TTS и причины недоступного звука обрабатывает сам CatQuest; его файлы и настройки не меняются.
- Отдельная галочка включает/выключает штатное отслеживание. Отображаемое состояние берётся из клиента.
- В карточках активных и дополнительных заданий есть «Открыть в» с независимыми кнопками **DungeonJournal → ForeverGuide → AzerothCompendium**. Кнопка появляется только для загруженного совместимого источника с этим заданием; без источников нет пустого блока. Выбирается точная страница по ID и крыло источника, а не открытый этаж. Наличие аддона не создаёт кнопку для отсутствующего в его каталоге квеста.
- «Дополнительные» — строго объединение каталогов **AzerothCompendium**, **ForeverDungeonJournal** и **ForeverGuide / Путеводитель Forever**. Одинаковые ID объединяются; активные и уже выполненные неповторяемые задания исключаются. Подтверждённые повторяемые задания не исчезают из-за предыдущей сдачи. Фильтры своей фракции, расы и класса сохраняются, но минимальный уровень и незавершённая цепочка сами по себе не скрывают квест. Questie не добавляет задания в этот раздел. Если один источник не установлен, используются остальные; если нет всех трёх — раздел пустой, без подмены на Questie. Наличие в каталоге не гарантирует, что сейчас выполнены условия получения.
- При совпадении записей приоритет заполненных текстовых полей: **DungeonJournal → ForeverGuide → AzerothCompendium**. Локализованный текст предпочтительнее непереведённого запасного; недостающие поля берутся из следующего источника. Для принятого задания текст и прогресс клиента остаются первичными.
- Данные обновляются событиями журнала и прогресса. Только состояние кнопки CatQuest проверяется каждые 0.25 с, пока карточка видима; списки и карта не перестраиваются этим опросом.
- Интерфейс RU/EN, штатные игровые шрифты, текстуры и подсказки предметов. Ресурсы игры не распространяются.

`/omqf` выводит диагностику текущей вкладки: instanceID, количество активных и дополнительных заданий, состояние индексации.

## Совместимость

Базовый интерфейс проверен с **OpenMap v0.8.8**, **Questie 12.9.0**, **OpenMap Dungeon Routes 0.1.3**, клиентом WoW Forever 1.60.1. Адаптеры каталогов и переходов рассчитаны на **AzerothCompendium 1.0.12**, **DungeonJournal 2.0.5**, **ForeverGuide 1.39.22**. Доступ к панели OpenMap изолирован в `Host.lua`, переходы — в `Navigation.lua`. Изменение внутренних интерфейсов источников может потребовать обновления адаптера.

Не меняются этажи, боссы, добыча, маршруты и штатный журнал. Если вкладка заданий отключена в настройках OpenMap, её замена также не показывается. Контроллер и боевые сценарии отдельно в живом клиенте не проверены; аддон не вызывает штатное открытие подробностей, не меняет защищённую компоновку WorldMapFrame и не расширяет заголовки журнала.

Каталоги источников читаются без изменения данных. DungeonJournal предоставляет общую таблицу, Compendium — зарегистрированный объект. Если аддон разрешает штатный `C_AddOns.GetAddOnLocalTable`, используется он. У ForeverGuide 1.39.22 таблица закрыта: наш отдельный модуль `OpenMapQuestFixGuideData` использует штатные относительные пути `.toc`, чтобы загрузить установленные файлы данных в **своё** пространство имён. Интерфейс ForeverGuide не загружается повторно. Переход открывает данж через его штатную команду и использует существующий обработчик реального результата поиска с совпавшим ID, без поддельных строк и доступа к upvalue. Индексация ожидается не более пяти секунд; закрытие окна, ручной поиск и смена нашей карточки отменяют ожидание. Чужие файлы, фильтры и предпочтение «Список/Дерево» не меняются; собственная история навигации источника обновляется обычным образом. Правка чужого `.toc` и `AllowAddOnTableAccess` не требуются.

## Разработка и проверка

```powershell
uv sync --locked
uv run python tests/check.py
uv run python tests/installed.py --addons "<игра>/_forever_/Interface/AddOns"
uv run python tools/package.py
uv run python tests/package.py --tag v0.1.5
```

Архив: `dist/OpenMapQuestFix-0.1.5.zip`; внутри две устанавливаемые папки нашего аддона, без файлов данных внешних источников. Python/uv нужны разработчику, не игроку.

Lua 5.1-сценарии проверяют: крылья монастыря и родительские areaID, реальные массивы OpenMap, позднюю готовность базы, активные задания вне базы, неизменность свёрнутых заголовков, прогресс/статусы, индексы описаний, награды, отслеживание и восстановление исходных вкладок OpenMap. Дополнительно — объединение трёх каталогов, уникальные вклады источников, отсутствие Questie-подмены, исключение активных/выполненных, повторяемость и фильтры. `tests/installed.py` читает установленные модули, не копируя их в репозиторий.

Сценарии карточки проверяют возврат к тёмному списку без залипших стилей, сохранение прокрутки и явный ID в подсказках наград. Сценарии CatQuest проверяют чтение именно открытого квеста при другом выборе журнала, восстановление выбора после успеха/ошибки, очередь, остановку и отсутствие необязательного аддона.

В живом интерфейсе проверены два принятых задания монастыря на карте кладбища, описание, предметные награды и опыт, возврат, переключение отслеживания с восстановлением исходного состояния, сохранение карты/этажа/выбранного задания штатного журнала, переход на вкладку боссов и обратно, переход в библиотеку с теми же заданиями. Убийства целей, принятие/сдача заданий и контроллер не проверялись в игре; изменения прогресса и членства проверяются изолированными сценариями.

Для 0.1.1 в игре подтверждены загрузка изолированного каталога ForeverGuide без изменения исходных аддонов, объединённый список монастыря, два активных задания без дублей и дополнительное «Запоздалая расплата» (96800), отсутствующее в активных. Происхождение 96800 подтверждено из DungeonJournal и ForeverGuide; Compendium после собственного разделения на крылья это задание не включает. Проверки установленной базы отдельно подтверждают совместный вклад всех трёх источников для 1050. Исключение завершённых и переходы принятия/сдачи проверены изолированными сценариями без изменения заданий персонажа.

Для 0.1.2 проверены в игре штатное оформление описания и наград, кнопка CatQuest «Читать» с запуском пака для 1050 и состоянием «Стоп», чтение дополнительного 96800, сохранение карты/этажа/выбора штатного журнала. Внутренняя декоративная рамка скрывается на вкладке заданий и не перекрывает кнопку; внешняя рамка окна сохранена. Обработка отсутствующего CatQuest, ошибок чтения, очереди, длинных наград и изменения размеров проверена сценариями Lua.

Для 0.1.3 в игре проверены кнопки DungeonJournal и ForeverGuide для дополнительного 96800 (Библиотека при карте Кладбища) и AzerothCompendium для непринятого 17 «В Ульдаман за реагентами». Отсутствующая у Compendium запись 96800 не создаёт лишней кнопки. Lua-сценарии проверяют отсутствие/отключение источников, владельцев страниц, точный ID при одинаковых названиях, фильтры, отмену/тайм-аут, ошибки и переиспользование кнопок без устаревшего квеста.
После переходов подтверждено сохранение ID карты, этажа, масштаба, смещения карты и выбранного задания штатного журнала; задания персонажа не принимались и не отменялись. Файлы источников не менялись.

Для 0.1.4 проверены все три перехода из активного задания 1050 «Мифология Титанов» и сохранение карты/этажа/выбора штатного журнала. Отсутствие 96800 в установленном каталоге Compendium отдельно подтверждено чтением его данных.

Для 0.1.5 после чистого `/reload` в карточке «Во имя Света» (1053) видны все четыре награды на выбор: Меч безмятежности (6829), Костекус (6830), Чёрная угроза (6831), Сфера Лорики (11262). Проверены включённые и выключенные три путеводителя и сохранение выбранного задания журнала. Незакэшированные названия и восстановление выбора при ошибке дополнительно проверены Lua-сценариями. Временная диагностика удалена; подсказки и ссылки выбора привязаны к фактическому ID предмета, а не к индексу урезанного запроса.

## CI и релизы

GitHub Actions запускает сценарии Lua 5.1, собирает ZIP и проверяет его состав при каждом push и pull request. Проверки не требуют установленной игры или чужих баз. Готовый ZIP доступен в артефакте запуска **Checks and release**.

Для публикации обнови одинаковую версию в обоих `.toc`, добавь запись в `CHANGELOG.md` и отправь изменения в `main`. Затем создай аннотированный тег `v<версия>` на проверенном коммите `main` и отправь его в origin. Например, текущий релиз: `git tag -a v0.1.5 -m "OpenMap Quest Fix 0.1.5"` и `git push origin v0.1.5`.

Тег должен совпадать с версиями обоих модулей; его коммит обязан принадлежать `main`. После успешных проверок workflow создаёт GitHub Release, прикрепляет `OpenMapQuestFix-<версия>.zip` и только затем публикует релиз. Повторный запуск не заменяет отличающийся уже опубликованный файл. Архив содержит только две наши папки; базы и ресурсы внешних аддонов не включаются.
